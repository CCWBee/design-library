Tab bar

Navigation family · glass register · ontology cell navigation / tab-bar / glass

A floating bottom bar for switching top-level views, blurred so the page reads through it. The selected item takes a brighter-tint pill and the accent ink; everything else stays quiet. Built as app navigation, so it is a nav of links carrying aria-current, not a tablist. Try it with the keyboard: tab through the live specimen to see the focus ring.

Live

The working component. Selecting a tab moves the pill; the others return to rest.

States

Every state forced statically so the sheet reads without a pointer. Default is the resting inactive tab; selected is the current view. Pressed and selected are distinct: one is a momentary touch, the other a persistent position.

Default Hover Focus Pressed Selected Disabled
  • DefaultInactive view, quiet ink, no fill.
  • HoverFaint fill, ink lifts to full contrast.
  • Focus-visibleAccent ring with a halo, keyboard only.
  • PressedDeeper fill for the touch, momentary.
  • SelectedBrighter pill, accent ink, aria-current.
  • DisabledReduced-alpha ink, no pointer, no fill.

Size and layout variants

Standard is the stacked icon-over-label bottom bar. Compact puts icon and label on one row for a slimmer bar or wider screens. Icon-only drops the labels for dense contexts; each target keeps its name through aria-label and a tooltip.

On loading: a top-level navigation tab bar has no loading state of its own. It stays present and responsive while the view it points at loads; any progress belongs to that view, not to the bar. So none is shown here. Accessibility notes: the bar is a landmark nav with a label, the current view carries aria-current="page", focus is always visible with a ring that clears the glass, targets meet the 44px minimum on the standard size, and the component honours prefers-reduced-transparency (blur off, opaque fill) and prefers-reduced-motion (transitions off). All ink and fills use alpha colours; the CSS opacity property is not used anywhere.
